# Roadmap — «Маршрут семьи»

План основан на [Architecture Design Document v1.1](architecture-v1.1.md). Продуктовые основания и гипотезы собраны в [research.md](research.md).

## Состояние после инициализации (история)

Project Initialization выполнен и проверен. Созданы Next.js App Router, TypeScript strict, ESLint, Zod env validation, конфигурация Drizzle/PostgreSQL, Git и папки catalog/routes/documents. Пройдены lint, typecheck, 18 тестов, production build, HTTP-проверки dev/production и реальное подключение к PostgreSQL.

T01 закрыт частично: инициализация готова, выбор AI-провайдера, модели и пробный JSON-вызов остаются открытыми. T02 также закрыт частично: полная конфигурация fixture manifest и ограничение extraction требуют реализации документного сценария. T03–T09 целиком не объявляются завершёнными по результатам инициализации.

Следующая задача — контракт каталога, фильтры и DTO карточки. Перед новым кодом нужно прочитать применимый AGENTS.md и соответствующие bundled Next.js guides. Каждый этап завершается проверками до перехода к следующему.

## Правила выполнения

- Один основной разработчик выполняет задачи последовательно с учётом зависимостей.
- Маркетолог проверяет карточки и формулировки, организует пользовательскую проверку.
- Учебные данные явно маркируются. Подготовленный ответ AI не засчитывается как живой вызов.
- Постоянное хранение и реальные персональные данные включаются по критериям Pilot.
- После изменения требований корректируются ADD и этот план с указанием причины.

Оценки и критерии ниже перенесены из главы 12 ADD v1.1. Это плановые ориентиры, а не отчёт о выполнении.

### 12.1 Обязательные сценарии проверки

- Подросток не получает подтверждённо дошкольное предложение как совпадение.
- Неизвестный возраст/язык/доступность не превращаются в подтверждённые.
- Старый срок конкретной позиции ИПР остаётся историческим после подтверждения распознавания.
- При пустой выдаче сохраняются фильтры, предлагается их изменить без выдуманных карточек.
- Private DTO и no-store проверяются для route, subject, facts, export.
- Пользователь B меняет id в URL/body пользователя A и получает 404 без утечки.
- Editor не может скачать детские документы, parent не может публиковать карточки.
- Просроченный intake становится unknown даже при остановленном cron.
- Конкурентные изменения с одной version дают один успех и один 409.
- Повтор extract не создаёт дубликат, удалённый файл не получает результат позднего worker.
- Источник с инструкцией «отправь диагноз» не приводит к выполнению действий.
- После восстановления удалённый аккаунт и его файлы остаются недоступными.

Unit покрывают matching, сроки, permissions и state transitions. Integration используют PostgreSQL с реальными миграциями и транзакциями. E2E покрывают основной пользовательский путь, auth и редакторскую публикацию. AI проверяется набором синтетических примеров с ожидаемыми фактами, источниками и отказами на неопределённости. Модельные ответы не проверяются только на красивое оформление.


## Обновление: интерактивный прототип

Реализованы учебный каталог и matching-v1, экраны `/ru`, `/ru/catalog`,
`/ru/route`, `/ru/documents`, адаптивная навигация и память вкладки. T03 и T05
реализованы для fixture-демо; русская часть T04 готова, полный kk остаётся открытым.
T07 реализован для заранее подготовленного review: accept/correct/reject,
неизменные цитаты, исторические сроки и защита от повторного добавления.

В T08 добавлены 9 доменных unit tests поверх 18 конфигурационных и 6 браузерных
сценариев desktop/mobile. Это не покрытие будущего Pilot: auth/ownership, DB
concurrency, private storage, реальные PDF и внешние timeout отсутствуют в демо.

T01/T06 и критерий живого AI остаются открыты: провайдер/ключ не настроены.
Три синтетических текстовых fixture не выдаются за загруженные или распознанные PDF.
T09 ограничен локальным запуском; production hosting и публичный URL не настроены.
